Нативное приложение на React Native и TypeScript для импорта синтетической банковской выписки. Используется исходный локальный mock из задания. Никаких внешних API, банковских данных и учетных записей не требуется.

Подготовка чистого проекта

После распаковки архива откройте папку statement-import и выполняйте команды из нее. Нужны Node.js от 20.19, npm, Xcode с установленным iOS Simulator, CocoaPods, Android SDK и Java 17. На машине проверки используются Node.js 26.4.0, npm 11.17.0 и CocoaPods 1.17.0. Первый запуск скачивает зависимости из интернета. Дальнейшая работа приложения и mock локальная.

```sh
npm ci
npm run check:kit
npm run fixtures
npm run prebuild
```

Сервер в отдельном терминале

```sh
npm run mock
```

Mock работает на http://127.0.0.1:8787. Для физического устройства нужен явно выбранный локальный адрес компьютера. Адрес можно изменить в настройках приложения до начала операции. Сервер не нужно публиковать в интернете.

Android

Запустите Android emulator. JAVA_HOME должен указывать на Java 17. ANDROID_HOME должен указывать на каталог Android SDK. Пример для macOS с установленной Temurin 17:

```sh
export JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home
export ANDROID_HOME=$HOME/Library/Android/sdk
npm run android -- --variant release --no-bundler
npm run fixtures:android
```

Скрипт подготовки выполняет adb reverse для порта 8787 и копирует только синтетические файлы в Downloads. При нескольких эмуляторах передайте идентификатор: node scripts/seed-fixtures.mjs android emulator-5554. В системном выборе документа откройте Downloads.

iOS

Запустите iOS Simulator. Приложение использует scene lifecycle, совместимый с новым требованием iOS 27. На Xcode 27 для ресурсов зависимостей явно задается минимальная версия 15.1.

```sh
pod install --project-directory=ios
xcodebuild -workspace ios/Statement.xcworkspace -scheme Statement -configuration Release -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17e' -derivedDataPath build/ios IPHONEOS_DEPLOYMENT_TARGET=15.1 CODE_SIGNING_ALLOWED=NO
xcrun simctl install booted build/ios/Build/Products/Release-iphonesimulator/Statement.app
npm run fixtures:ios
xcrun simctl launch booted com.nikitasokolov.statementimport
```

Если название вашего симулятора отличается, замените только name в destination. В Files откройте Обзор, На iPhone. Здесь лежат исходные синтетические файлы. Они также доступны в папке Statement. Скрипт размещает их только в выбранном симуляторе и не перезаписывает отличающийся документ в корне Files. Для конкретного симулятора скрипт принимает UUID: node scripts/seed-fixtures.mjs ios UUID.

Обе сборки содержат JS внутри нативного приложения. Metro для проверки release не нужен. Это не Expo Go и не web.

Автотесты

```sh
npm test
npm run test:mock
npm run typecheck
npm run check:kit
```

Тесты клиента запускают настоящий HTTP mock на случайном локальном порту. Проверяются оба корректных файла, SHA-256 отправленных байтов, сохранение ключа до POST, восстановление потерянного ответа, гонка с GET 404, устаревшая ревизия, отказ удаления, повтор с прежним ключом, запрет подтверждать удаление одним DELETE, очистка копий и отсутствие повторного POST после перезапуска. Файлы исходного набора сверяются с SHA-256 архива задания.

Нативные E2E

Используется Maestro CLI 2.12.1. Установите Maestro по официальной инструкции https://docs.maestro.dev/getting-started/installing-maestro и оставьте mock запущенным. Перед прогоном установите приложение и подготовьте фикстуры. Команды выполняются по очереди, потому что сценарии сбрасывают один общий mock. Каждый независимый сценарий очищает данные только тестового приложения.

```sh
npm run e2e -- emulator-5556
E2E_PLATFORM=ios npm run e2e -- E614BFAC-5DB9-46F6-A928-65BD58E942AC happy invalid
```

Замените идентификаторы на свои. Для другого пути к CLI задайте MAESTRO_BIN. Скрипт проверяет результат UI, счетчики сервера, объем и SHA-256 принятых байтов. Во время проверки крупного шрифта он ставит font_scale=2.0 и затем возвращает прежнее значение. Android flows рассчитаны на английский системный Files picker, iOS flows на русский Files.

Ручная проверка

В настройках приложения есть диагностика и выбор режима mock. Перед независимым сценарием удалите текущий импорт, дождитесь подтверждения и сбросьте тестовый сервер. Счетчики можно сверить командой:

```sh
curl http://127.0.0.1:8787/__test/state
```

happy. Выберите statement.csv или statement.pdf, проверьте имя, размер и формат, подтвердите отправку. Готовый отчет содержит StreamBeam 19.99 AUD и BrightGrid 132.00 AUD. Общая сумма 151.99 AUD в месяц. Подробнее открывает карточку с датой последнего списания. Отчет появляется только после ready.

lost_ack. Выберите режим до отправки. После потери ответа закройте приложение и запустите его снова без очистки данных. Клиент найдет job через GET по сохраненному ключу. newJobs и createRequests должны остаться равны 1. Можно также нажать Проверить и восстановить. При GET 404 это действие повторит POST с тем же ключом и теми же байтами.

stale_status. После ready приходит processing с меньшей ревизией. Отчет остается на экране. Диагностика показывает ревизию 3 и отброшенный ответ.

delete_failure. Отправьте корректный файл, дождитесь отчета и запросите удаление. После HTTP 503 приложение сообщает, что удаление не подтверждено. Переключите режим на happy и повторите удаление. Ключ удаления останется прежним. Успех показывается только после GET со статусом deleted.

spoofed.pdf и oversize.csv. Выберите каждый файл. Клиент покажет ошибку до POST. createRequests до и после выбора не меняется. Временных копий после отказа должно быть 0. Исходные файлы остаются доступными в системном picker.

Дополнительно проверьте отмену системного выбора, отмену на экране подтверждения, возврат после перезапуска до отправки, потерю сети и крупный системный шрифт. Во всех случаях ключ существующей операции сохраняется, а недостоверный успех не показывается.

Устройство приложения

App.tsx содержит экраны. src/core.ts содержит состояние и переходы операции без зависимости от React Native. src/api.ts реализует HTTP-контракт. src/native.ts отвечает за системный picker, приватные копии и AsyncStorage. plugins/withSceneLifecycle.js добавляет нативный жизненный цикл окна iOS при prebuild. Каталоги ios и android генерируются из конфигурации и не входят в исходники.

Состояние одной операции хранится до завершения удаления. Автоматическая проверка делает только GET. После неизвестного исхода повторная отправка требует действия пользователя. Ошибки сети не удаляют последний подтвержденный результат.

Релизные ограничения и очистка описаны в RELEASE.md. Принятые решения и упрощения описаны в SELF_REVIEW.md. Результаты прогонов находятся в evidence.
