Release note 1.0.0

Это локальное тестовое приложение для вымышленных выписок. Сервер и тестовые файлы из задания не изменены. Приложение не публиковалось в магазинах.

Разрешения

Android использует доступ к сети и системный выбор отдельного документа. Доступ ко всему хранилищу, микрофону, камере и контактам не нужен. iOS использует системный Files picker. Для локального HTTP включены разрешения на незашифрованное соединение. Перед реальным выпуском нужен HTTPS и удаление этих исключений.

Копии файла

Исходный файл остается у пользователя. Системный picker создает копию в кеше приложения. Проверка читает не больше 4096 байт начала и 1024 байт конца. После проверки файл перемещается в statement-pending внутри приватного кеша. Отправка использует нативную загрузку файла по его локальному пути, без преобразования всего файла в строку или массив JavaScript.

После подтвержденного приема сервером приватная копия удаляется. При неизвестном исходе отправки она сохраняется для повтора с тем же ключом. Отмена выбора удаляет копию. При запуске удаляются неиспользуемые файлы приватного кеша и кеша picker. Если система сама очистила кеш, клиент не подменяет документ и не отправляет другой файл под старым ключом.

В AsyncStorage хранится минимальное состояние операции, адрес сервера и ключи. До приема сервером сохраняются также путь, имя, размер и формат выбранного файла. После приема эти поля удаляются. Подтверждение удаления сохраняется, чтобы поздний ответ не вернул старый отчет.

Данные диагностики

В клиенте нет аналитики, crash SDK и записи содержимого документов в логи. Диагностика показывает только счетчики запросов, ревизию и число временных копий. Mock хранит метаданные и SHA-256, но не исходные байты. Его состояние находится в mobile-engineer-kit/.mock-state.json.

Очистка

Удалить импорт в приложении и дождаться подтверждения сервера. После этого в диагностике можно сбросить локальный тестовый сервер. Удаление приложения очищает его локальные данные, но само по себе не удаляет данные сервера. Исходные файлы из Downloads или Files удаляются отдельно пользователем. Файлы, которые скрипт подготовки кладет в Documents приложения и в корень Files симулятора iOS, являются исходными синтетическими примерами, а не приватными копиями импорта. Общий доступ к Documents включен только для удобства этой проверки.

Условия остановки rollout

Повторное создание job для одной операции, ложное подтверждение удаления или попадание содержимого документа в телеметрию требуют немедленной остановки выпуска. Также нужно отслеживать рост ошибок восстановления, недоступных временных файлов и зависших удалений. Метрики должны содержать тип ошибки и версию приложения, без имен файлов и содержимого выписок.

Граница обновлений

Новый нативный бинарник нужен при изменении разрешений, ATS, Android manifest, нативных библиотек, Expo SDK или React Native. JS исправления интерфейса и логики можно доставлять через OTA только при совместимом runtime и уже настроенном механизме обновлений. В этом проекте OTA не подключен, поэтому поставка новой версии выполняется новой сборкой. Android release подписан локальным тестовым ключом и не предназначен для магазина.

Зависимости

Версии Expo и React Native зафиксированы в package-lock.json. npm audit на дату проверки сообщил 17 предупреждений в дереве зависимостей, включая 2 high для image-size и postcss. Это зависимости инструментов обработки изображений и CSS, приложение не принимает такие документы для обработки этими инструментами. Полный результат сохранен в evidence/dependency-audit.json. Перед production нужен отдельный пересмотр SDK и проверка обновлений. Принудительная смена основной версии SDK в готовый проверенный бинарник не вносилась.
